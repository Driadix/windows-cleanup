# Тестовые прогоны windows-cleanup

Журнал тестовых прогонов скилла: что гоняли, какие баги/UX-затыки нашли, что поправили.
Каждый прогон — отдельная секция с датой. Полная диагностика по шагам — в
`pc-cleanup-logs/<дата>/observations.md` рабочей папки прогона.

---

## Прогон 2026-08-18 (полный, фазы 0–10; версия скилла 0.2.1 → 0.2.2)

Среда: Windows 10 Pro 19045, PS 5.1, профиль планктон (кириллица), TEMP перенаправлен на D:.
Диски: C: 148 ГБ (свободно 51,6), D: 298 ГБ (свободно 136,8). Ctrl-диск — SATA SSD Kingston.

### Применено (по решениям пользователя)
- Тени C:: лимит UNBOUNDED → **10 ГБ** (`vssadmin resize /maxsize=10GB`): 16,9 → 5,82 ГБ использовано,
  свободное место C: 51,62 → 63,43 ГБ (**+11,81 ГБ**). D: теней нет.
- Автозапуски: MSIAfterburner и RazerCortexScheduleClean disabled, задача Nova удалена,
  RazerCortex снят с HKLM Run (100 → 98 живых; верифицировано повторным autostart.ps1).
- Мусор/кэши (~1,5 ГБ), программы, профиль, корзины — **не удалялись** (решение пользователя «ничего не удалять»).

### Найденные баги скилла (закрыты в 0.2.2)
1. `scan.ps1 -MinDupBytes 50MB` из командной строки падал
   (`ParameterArgumentTransformationError`: `"50MB" -> Int64 not in correct format`) — суффикс валиден
   только как литерал-дефолт в теле скрипта. → параметр стал строкой, парсинг через новую `ConvertTo-Bytes`
   (в `cleanup-common.ps1`): `'20MB'`, `'1.5GB'`, голые байты.
2. `scan.ps1` писал в фиксированные `dirs_top.txt/files_top.txt/dupes.txt` — второй скан (D:) затирал
   первый (C:). → параметр `-Tag 'c'`: имена `dirs_top_c.txt`, `dupes_d.txt`.
3. `shortcuts.ps1` ждал `-OutDir`, остальные phase-скрипты `-Work` (в тексте SKILL.md имя не было
   задокументировано). → параметр `-Work` с алиасом `-OutDir`.
4. `run-elevated.ps1 -Args` из git-bash не работал даже «словами раздельно» (bash срезает кавычки, PS
   видит `-Work` как параметр → PositionalParameterNotFound). → надежный мост: env `PC_ELEV_ARGS`
   построчно (одна строка = один аргумент). Памятка в шапке и Pitfall в SKILL.md переписаны.
   Замечание: первый вариант (Invoke-Expression `@(...)`) сам оказался багованым (`-Work` парсится как
   команда) — поймано верификацией, заменено.

### Открытые замечания → закрыты в 0.2.3
- ~~`inventory-quick.ps1`: колонка `installed.csv` названа `SizeMB`, но хранит сырой `EstimatedSize` в **КБ**~~ →
  **закрыто**: `SizeMB` делит на 1024 (LoL теперь ~38 567 МБ = 37,7 ГБ).
- ~~`ledger-report.ps1`: при 0 удалений строка «ИТОГО освобождено» печатает пустое число~~ →
  **закрыто**: `$totalMB` обнуляется при `$null` от `Measure-Object` пустого набора.
- ~~Ворота дисков (Фаза 1): вопрос-тул с `multi_select=true` позволял противоречивый выбор~~ →
  **закрыто**: в SKILL.md и inventory.md — одиночный выбор (radio) без пересекающихся вариантов.
- ~~`scan.ps1`: пара Edge vs EdgeWebView2 (by-design дубль) попадала в `dupes.txt` пользовательских~~ →
  **закрыто**: префиксы `EdgeCore`/`EdgeWebView` (Program Files и x86) добавлены в системный список дублей.

### Агент-ошибки вызова из git-bash (обучающие кейсы)
- Экранированный `\$DATE` в пути не раскрывается (привет `pc-cleanup-logs$DATE`).
- `-Disks 'C','D'` → один аргумент `C,` — все кэши помечены «вне выбранных». Проверять кеш-флаги после запуска.
- `$` в `-Command "..."` из двойных кавычек bash съедаются → одинарные кавычки.

### Диагностика
Полный журнал: `pc-cleanup-logs/2026-08-18/observations.md` (13 записей: 2 error, 4 warn, 7 info).

## Прогон 2026-08-19 (внешний, на чужой машине через opencode; версия скилла 0.2.3)

Среда (логи от друга): Windows 10 Home 19045, PS 5.1.19041, профиль `Nitro`, диск C: 476 ГБ NVMe
(HFM512GDJTNG), свободно на старте 24,84 ГБ. Скилл склонирован в `~/.config/opencode/skills/`.
Логи — в `2026-08-19/` (в репозиторий не индексируются, в `.gitignore`).

### Результат прогона
- Фаза 4 user-проход выполнен: **освобождено 56,88 ГБ** (баланс ledger: 24,84 → 81,49 ГБ).
- Фазы 7 (автозапуски) и 8 (битые ярлыки) в конце сессии выполнены (10 автозапусков, 43 ярлыка).
- Elevated-проход **не выполнялся** (по решению пользователя после неудач с подъёмом прав);
  DISM и тени (`vssadmin list shadowstorage`) не делались. Фазы 9–10 не завершены.

### Найденные корневые баги скилла (закрыты в 0.2.4)
1. **Все `.ps1` в репо были UTF-8 БЕЗ BOM** — PS 5.1 на ru-RU читает их как ANSI/cp1251, кириллица в
   строках-литералах ломает парсинг («падал на парсинге кириллицы»). Друг перекодировал копию в BOM
   вручную. → **фикс**: BOM во все 14 скриптов + проверка BOM в `tools/validate.py` + правило в
   SKILL.md/README. Судя по логике и таймингу, до фикса доходило и до run-elevated.ps1,
   что отдельно ломало старт elevated-части (parse-check не пропускал).
2. **UAC-подъём из сессии агента молча не повышает**: даже после подтверждённого UAC процесс оставался
   Medium integrity (`diag_elevated.log: elevated: False`; `runas_test.txt` = `whoami /groups`, где
   группа Администраторы «включена, владелец» при МЕТКЕ High — то есть машина умеет, агент — нет).
   → **фикс**: (а) `elevated-cleanup.ps1` пишет `elevated: True/False` первой строкой лога;
   (б) `run-elevated.ps1 -ElevLog` верифицирует после `-Wait` и при False → exit 3 + понятный совет;
   (в) `phase0.ps1` предупреждает UAC-RISK при неинтерактивной + не-админ сессии.

### UX-проблемы → архитектурные изменения (0.2.4)
3. **Скан C: занял 22,6 мин** (`scan_c.log: в 1358,1 с`) — всю Фазу 2 пользователь ждал в тишине.
   → добавили `scan.ps1 -ProgressFile` (пульс для поллинга агентом) + мета-кэш `scan_meta_<tag>.txt`
   (не пересканировать при повторном показе). Фаза 2 перестроена: **quick-pass** (реестр/кэши/
   автозапуски/ярлыки — 1–3 мин, диск почти не трогает) → отчёт частями, **heavy-pass** в фоне с прогрессом.
   Тогда же пробовали `-FastEnum` (обход через `[System.IO.Directory]` вместо `Get-ChildItem`): на этой
   машине выигрыша он НЕ дал и **был удалён в 0.2.4** — см. раздел «Вердикт по .NET-обходу» ниже.
   UX-механизмы (фон + прогресс + мета-кэш + quick/heavy-разбиение) остались и работают.
4. Вывод `whoami /groups` в OEM-cp866 (`runas_test.txt`) — напоминание, что консольные
   redirect-файлы не стоит разбирать как UTF-8; логи скилла пишутся в UTF-8 (BOM не требуется).

### Обучающее для скилла
- dot-source `observe.ps1` из другого скрипта **нельзя было**: в нём был голый `exit` в теле → убивал
  вызывающего. Запуск только отдельным процессом (Start-Process). *(Закрыто в 0.3.0: `exit 0` → `return`,
  dot-source теперь безопасен; отдельный процесс остаётся просто дешевле.)*
- Кейс подтверждает: верить `-Verb RunAs`/exit-коду нельзя — надо проверять фактический уровень прав;
  и клиентский клон скилла может быть устаревшим/повреждённым — `tools/validate.py` по клону полезен.

## Живой прогон 0.2.4 на C: (2026-08-19, планктон)

Проверка новых механизмов на живом диске (148 ГБ, SATA SSD, 599 298 файлов на C:).

### Гибрид quick/heavy — работает
- 03:20 phase0 → 03:21 heavy-scan `-FastEnum -ProgressFile` в фоне; пока шёл скан — quick-pass
  (`inventory-quick` 252 программы, `autostart` 98 live, `shortcuts` 0/213, `steam-games` 102 ГБ,
  `unused-detect` 0) → «быстрая картина» мгновенно, тяжёлая догружается.
- Полный скан C: `-FastEnum`: 599 298 файлов за **296 с (~5 мин)**, пульс прогресса 120 строк,
  `DONE` в конце. Мета-кэш `scan_meta_c.txt` пишется (root/tag/сек/флаги).

### Сверка fast/classic — бит-в-бит идентичны
- Один корень `C:\Windows` прогоном classic и fast: `dirs_top/files_top/dupes` — **0 расхождений**.

### Найден и закрыт баг fast-обхода (важно)
- Первый полный C: упал ~190k файлов без `DONE` (запуск без redirect — ошибка ушла в скрытое окно).
  Причина: `.Length`/`.Attributes` у `FileInfo` вне try/catch — .NET-исключения (PathTooLong /
  UnauthorizedAccess на враждебном/недоступном файле) — terminating и **не** глушатся
  `ErrorActionPreference` (он ловит только cmdlet-ошибки), в отличие от classic `Get-ChildItem
  -ErrorAction SilentlyContinue`. → тело циклов файл/папка обёрнуто в `try { ... } catch { continue }`,
  после фикса полный C: прошёл до конца чисто (stderr пуст). Проверка на живом диске поймала то,
  что юнит-фикстура не ловила.
- Время: fast на C:\Windows 180 с vs classic 126 с (поддерево Windows — .NET выигрыша не даёт,
  выигрыш на больших пользовательских корнях: полный C: 5 мин vs 22 мин у друга на old-Get-ChildItem).

### Вердикт по .NET-обходу → откат к классике (0.2.4, финальное решение)
Сравнение на ЭТОЙ машине (SATA SSD, 599k файлов, одинаковые условия, полный C:):
- Полный C:: classic **287 с** vs .NET(FastEnum) **296 с** — паритет, классика даже чуть быстрее.
- C:\Windows: classic **126 с** vs .NET **180 с** — классика быстрее на 43%.
Вывод: `.NET EnumerateFiles(+стек)` НЕ даёт выигрыша нигде, местами медленнее. Причина — узкое место
не в способе перечисления, а в самом обходе NTFS-дерева через Win32 API. Единственный реальный
ускоритель (WizTree/Everything/SpaceSniffer читают MFT напрямую) — нативный код + админ, вне
PowerShell-скилла, и ставить сторонние инструменты пользователю скилл и не предлагает (см. Фаза 9).
Действие: `Invoke-FastWalk`/`-FastEnum` **удалены** — единственный обход снова классический
`Get-ChildItem -Recurse -Force`. Сохранены UX-части: `-ProgressFile` (теперь `# start` + `DONE\t<сек>\t<файлов>`
для поллинга фонового запуска), мета-кэш `scan_meta_<tag>.txt` (+ поле `files`), quick/heavy-разбиение.
Итог для рядового пользователя: скан запустится где угодно (только core cmdlets, никаких сторонних зависимостей),
никакой погони за мнимым ускорением — фон + прогресс + кэш вместо микрооптимизации.

## Прогон 2026-10-03 (C: + D:, планктон; ревизия скилла → 0.3.0)

Среда: Windows 10 Pro 19045, PS 5.1.19041, профиль `планктон` (кириллица), TEMP перенаправлён на D:.
Диски: C: 148 ГБ (свободно 51,61), D: 298 ГБ (129,32), E: VAULT 60 ГБ (Removable, exFAT — исключён).
Целевые тома по воротам Фазы 1: C: + D:. Heavy-scan: C: 743 071 файлов за 636 с, D: 302 058 за 174 с.

Прогон совмещён с ревизией скилла: 4 параллельных read-only агента (сканы / cleanup-скрипты / доки /
tooling), каждая находка перепроверена живым замером до правки.

### Корневые баги, найденные живым замером (не ревью-предположением)
1. **`Get-Volume .DriveType` — СТРОКА, а не enum.** Замер: `.GetType().FullName` = `System.String`,
   `[int]$_.DriveType` падает «Cannot convert value "Removable" to System.Int32». Значит фильтр
   `-ne 2` в `inventory-quick.ps1`/`steam-games.ps1` не исключал НИЧЕГО — съёмный E: просочился в
   `recyclebin.txt`. Питфолл в SKILL.md утверждал обратное. → добавлен `Get-FixedVolumes`
   (`DriveType.ToString() -eq 'Fixed'`), Pitfall переписан. Смоук-тест на машине с 1 съёмным томом:
   утечка 0.
2. **UserAssist читался не с того уровня реестра.** Замер: `{GUID}` имеет 8 служебных свойств и 0 путей,
   а в `{GUID}\Count` — 303 + 98 записей. Сигнал был полностью мёртв, работал один MuiCache.
   → чтение `Count`; следов запуска стало 361 → **513**.
3. **`Test-ProtectedRoot` блокировал собственную цель elevated-прохода.** DeliveryOptimization лежит под
   защищённым `\ServiceProfiles\`: замер `Test-ProtectedRoot(DO) = True` → `Remove-Contents` скипал все
   элементы, возвращал `done` и 0 байт, а ledger писал нулевую строку как успех. → точечный allow-list
   (DO + FontCache), `Protected(DO) = False`, при этом `Protected(WinSxS)/Protected(LocalService) = True`.
4. **`$b = $pr.Value` затирал счётчик `$script:B`** (имена PS регистронезависимы): сводка напечатала
   `broken=3 0 0 0 214 40 136...` — byte[] вместо числа. → переименовано в `$saBytes`; добавлен Pitfall.
5. **`residue-check.ps1 -Loc 'D:\Soft'` выдал 146 ложных «остатков»**: `-like '*Soft*'` совпадал с каждым
   DisplayName, содержащим «Micro**soft**». → `Test-NameHits` по границе слова (`\b` только у word-края
   термина, иначе `.NET` никогда не совпадёт) + `Test-SharedCatalog` (общий каталог помечается, остатком
   не считается). Тот же вызов: **146 → 16**, и все 16 — настоящие.
6. **`pending-delete.ps1` молча ничего не удалял при перезагрузке**: `MoveFileEx` удаляет каталог только
   если он ПУСТ, а в очередь ставилась сама непустая папка. → раскрытие в глубину (файлы → подкаталоги от
   глубоких к корню → корень). Порядок проверен на фикстуре из 5 файлов и 4 каталогов. Заодно
   `[string[]]@($existing)` — `AddRange(string)` на одноэлементном REG_MULTI_SZ реально кидает
   `MethodException` (воспроизведено).
7. **`scan.ps1`: самополлюция рабочей папки** при `-OutDir` с прямыми слэшами (`'D:/work'.StartsWith('D:\')`
   = False) и **`DONE` писался ДО записи выходов** — поллинг читал устаревшие файлы того же тега.
   → нормализация OutDir до сравнения; `DONE` перенесён последним; `FAILED` через `trap`. Проверка на
   живом дереве: рабочая папка в `dirs_top` = 0 ГБ, выходы существуют к моменту `DONE`.
8. **`ledger-report.ps1` печатал потерю места как освобождение** (`[math]::Abs`). → знак сохранён;
   синтетический ledger с baseline на 20 ГБ больше текущего дал `изм. свободного: -20,00 ГБ`.

### Переносимость (требование «без абсолютных путей, Win10+11»)
- `elevated-cleanup.ps1`: все цели с литерала `C:\Windows\...` переведены на `$env:SystemRoot` /
  `$env:SystemDrive` — на системе не на C: скрипт раньше молча чистил ничего.
- `inventory-quick.ps1`/`shortcuts.ps1`: пути установщиков и ярлыков через shell-folders +
  User Shell Folders (OneDrive KFM: литерал `$env:USERPROFILE\Desktop` был бы пуст).
- `steam-games.ps1`: `Get-Content -Raw` без `-Encoding UTF8` читал `libraryfolders.vdf` (UTF-8 без BOM)
  как cp1251 → кириллический путь библиотеки терялся целиком; добавлен v1-формат vdf и `SteamPath`.
- `run-elevated.ps1`: квотинг аргументов с пробелами (обещание `PC_ELEV_ARGS` не выполнялось),
  отменённый UAC → exit 4 вместо необработанного исключения, проброс exit-кода, exit 5 при отсутствии лога.
- `Get-ExePath`: схлопывание `\\` сохраняло UNC (`\\srv` → `\srv` = ложный BROKEN). Проверено на 7 кейсах.
- Убраны мёртвые `Get-VolumeBrief`/`Test-LnkAlive`; `Test-UrlBroken` больше не дублируется в `shortcuts.ps1`.
- `tools/validate.py` дополнен: BOM-проверка для `tools/*.ps1`, детектор machine-bound путей
  (в коде = ошибка, в комментариях = warning), дрейф «скрипт есть, но не описан в SKILL.md».
  Результат: исполняемый код чист, предупреждений 14 → 5.

### Скорость (замеры на этой машине)
- `steam-games.ps1`: **~минуты → 1,9 с** — размер берётся из `SizeOnDisk` в `appmanifest_*.acf`,
  обход дерева только fallback. Сумма 105,37 ГБ vs 105,08 ГБ (обход) — расхождение в пределах шума.
- `unused-detect.ps1`: 70,6 с; убран ДВОЙНОЙ обход каталога приложения (`Get-SizeBytes` + `Get-ChildItem
  -Filter *.exe`) и обход общих корней (`Program Files` на каждую запись реестра = десятки минут).
- `cleanup-common.ps1`/`elevated-cleanup.ps1`: убраны мёртвые обходы «до» (в `Remove-Contents` `$before`
  вычислялся и не использовался; в elevated — внешний `Get-SizeBytes` дублировал внутренний).
  Было до 3 полных обходов одной цели (Windows\Temp может быть гигабайты).
- `scan.ps1`: `Sort-Object { scriptblock }` на строках дублей → сортировка по числовому свойству
  (ровно то, от чего предостерегал собственный Pitfall).

  Steam `htmlcache` (411 МБ) + `shadercache`, Discord Cache (170 МБ) + Code Cache, VS Code Cache

- Elevated-проход: `Windows\SystemTemp` (Win11 24H2+), `Logs\CBS`, `WER` (ProgramData), `Minidump`,
  `LiveKernelReports`, `MEMORY.DMP`, `$SysReset`, FontCache, `Windows.old` (по флагу `-WindowsOld`,
  только с явным согласием — убирает откат ОС).
- Автозапуски: `WOW6432Node\RunOnce` (отсутствовал), Winlogon `AppSetup`/`VmApplet`, **StartupApproved**
  (вкл/выкл + FILETIME + сироты). Живой результат: 20 записей, 12 сирот — включая `RazerCortex`

  Startup-папках действительно нет — проверено).
- Ярлыки: покрытие 223 → **381** живой + найдено **2 битых**, которые прежние «4 места» не видели вообще
  (Quick Launch: `EaseUS Partition Master.lnk` → `D:\Soft\EaseUS...`, отсутствующий в `D:\Soft`;
  `ProComps.lnk` → `D:\asdfasdf\overwolf\OverwolfLauncher.exe`, каталога нет). Обе цели проверены `Test-Path = False`.
