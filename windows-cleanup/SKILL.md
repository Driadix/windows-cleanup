# Windows Cleanup Skill

Полуавтоматический воркфлоу освобождения места на Windows 10/11: инвентаризация, очистка мусора и кэшей, удаление программ по выбору пользователя, зачистка профиля/остатков/автозапусков, битых ярлыков. Скилл **не** автоматический: каждое необратимое действие проходит через **ворота** — явное решение пользователя. Скилл **не** занимается безопасностью (никаких проверок антивируса, сети, портов) — только место и мусор. Цель — место, не производительность.

Язык общения с пользователем — русский. Все пути — с учётом кириллического профиля (`-LiteralPath` везде).

**Язык и тон.** Человечное, но техническое общение: коротко, по делу, без канцелярита и «машинных» оборотов. Всегда структурируй (таблицы, №-ID), указывай размеры, пути и однозначные последствия. О месте — всегда «свободное место: было X → стало Y, **освободилось N ГБ**» (никогда «размер диска изменился» без уточнения). Активно задавай уточняющие вопросы через ворота, если решение неоднозначно. Перед необратимыми действиями говори заранее, что произойдёт и что пользователь увидит (например, «сейчас может открыться окно деинсталлятора — это нормально; это сама программа, а не скилл; подтверди или дождись»).

## When to Use

- «Почисти комп / освободи место / убери мусор, кэши, лишние программы»
- «Что можно почистить / что у тебя есть?» → отвечай списком фаз с оценочными результатами, затем по выбору пользователя
- Точечная просьба → входи ровно в нужную фазу («почисти корзину / браузер», «найди дубли», «проверь автозагрузку»)

**Don't use for:** macOS/Linux (вообще не наш случай); антивирусные проверки и «поиск вредоносного»; разгон/оптимизация производительности; полномасштабная автоматизация без контроля пользователя.

## Prerequisites

- Windows 10 или 11, PowerShell 5.1+. Детектируй ОС сам: `Get-CimInstance Win32_OperatingSystem` (Caption, BuildNumber) + `$PSVersionTable` — ветвление Win10/11 только по 4 пунктам: winget, Teams, WSL из Store, Storage Sense. Пользователя про ОС не спрашивай.
- **Права**: стартуем пользовательской сессией. Админ нужен → не просим заранее, а говорим «сейчас появится окно UAC — подтверди» и запускаем `Start-Process -Verb RunAs -PassThru -Wait`.
- **Рабочая папка** (логи/скрипты/результаты сканов): `%USERPROFILE%\Documents\PC-Cleanup\<дата>\`. Если у текущей сессии есть явный рабочий каталог проекта — клади логи в него в подпапку `pc-cleanup-logs\`. **Никогда** не в %TEMP% (TEMP — цель очистки и часто перенаправляется). Рабочая папка **исключена из очистки**.
- `%TEMP%` берём только из `$env:TEMP`, никогда не хардкодим путь.

## How to Run

Полный воркфлоу — процедура ниже, фазы 0–10. Точечный запрос — нужная фаза(ы): контекст (0) и ворота дисков (1) проходятся быстро, затем целевая фаза. Скрипты-помощники лежат рядом со скиллом в `scripts/`; путь к папке скилла — `skill_view` (поле `skill_dir`) или `${env:USERPROFILE}\AppData\Local\hermes\skills\maintenance\windows-cleanup\`. Запуск: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<skill_dir>\scripts\<имя>.ps1" <аргументы>`.

## Procedure

Каждая фаза заканчивается **критерием завершения**; между фазами не останавливаемся без необходимости. Останавливаемся **только на воротах**. После каждой фазы — запись в **per-phase лог** и **кумулятивный репорт-файл** (UTF-8): фаза, что удалено, сколько освобождено накопительно. Прогресс зеркалится в todo-инструмент; шаг помечается completed **только после прохождения верификации**.

### Фаза 0. Контекст
`Get-CimInstance Win32_OperatingSystem`, `whoami`/`$env:USERPROFILE`, `Get-Volume | Where DriveLetter`, `$env:TEMP`, проверка текущих прав (`IsInRole('Administrators')`). Создай рабочую папку. Запиши контекст первой строкой лога. **Обязательно зафиксируй baseline свободного места всех целевых томов в `ledger.csv`** — без него Фаза 10 не сможет честно посчитать дельту. Всё это делает `scripts/phase0.ps1` (контекст + ledger).
**Критерий:** карта дисков (буква, метка, размер, свободно) и версия ОС — в логе; рабочая папка создана; baseline в ledger.csv.

### Фаза 1. Ворота дисков
Дисков >1 и пользователь не уточнил → **стоп, вопрос-тул с мультивыбором**: перечисли диски с DriveType и размером; съёмные (Removable) и сетевые (Network) исключены по умолчанию, их можно включить только явно. Корзины чистим только по выбранным дискам.
**Критерий:** явный список целевых дисков зафиксирован в контексте.

### Фаза 2. Инвентаризация
Сканы — **последовательно в фоне по умолчанию** (стабильно, без пиковой нагрузки на диск); вариант «быстро — параллельно» только по явному выбору пользователя с предупреждением о нагрузке (см. CH/наблюдения — параллельные сканы конкурируют за диск и суммарно медленнее). **Набор корней — без пересечений** (не сканируем C:\Users целиком И отдельно AppData — берём профиль один раз; рабочая папка исключена из обхода). Карты корней — `scripts/scan.ps1` (один проход по дереву). Источники — `references/inventory.md`. Собери:
- карты папок (топ-50 по размеру) на целевых дисках + ProgramData + AppData*;
- топ крупных файлов;
- список программ из 3 веток реестра Uninstall (HKLM + WOW6432Node + HKCU) → **`installed.csv`** (с флагом `LocExists` и Hive), установщики, корзины, кэши — `scripts/inventory-quick.ps1`;
- установщики в Desktop/Downloads/Documents;
- корзины по выбранным дискам (только файлы `$R*`);
- кандидаты дубликатов (группировка Name+Length, фильтр >50 МБ; системные пути — в `dupes_system.txt`);
- **артефакт `unused_hints.txt`** (сигналы MuiCache/UserAssist + даты установки/папок; негативные фильтры: автозапуск/задачи/процессы; оговорки про CLI-тулы и чужие лаунчеры) — `scripts/unused-detect.ps1`; материал для блока 🔵 в Фазе 3 и кандидатов Фазы 5;
- **артефакт `steam_games.txt`** (топ игр Steam по размеру из `steamapps\common` + библиотек по `libraryfolders.vdf`) — `scripts/steam-games.ps1`; это ИНФОРМАЦИЯ «где место», НЕ кандидаты: удаление игр Steam — только через клиент. Принцип: показать место — всегда; кандидатами на удаление — только то, что чистится одним движением.
**Критерий:** по каждой цели результат записан в файлы сканов в рабочей папке; ни одна цель не удалена.

### Фаза 3. Отчёт + ворота согласия
Составь отчёт по **протоколу списка**: таблицы-блоки, у каждой строки №-ID, путь, размер, риск (🟢 мусор/кэш · 🟡 программа · 🔴 данные · 🔵 возможно не используется), рекомендация. Блок 🔵 строится из `unused_hints.txt` фазы 2 — только кандидаты, решение за пользователем. Покажи **итог сверху** и подытоги по категориям. Представь пользователю решение: «удалить 1,2,5-7» / «все кроме 3,8» / «только 4». Короткие списки (<10) — продублируй в вопрос-тул с мультивыбором.
**Ворото-правила:**
- «Мусор/кэши» — можно группой **после показа размеров**;
- «Программы» — всегда список → вопрос;
- «Данные/сейвы» — отдельный вопрос с предупреждением о риске;
- «Системное» — только с объяснением (см. Фаза 9);
- **«Неизвестное»** (объект без происхождения, как `C:\Windows\392667600.dat`) — расследовать (дата создания, тип, подпись, происхождение) → показать → спросить. **Удалять нельзя молча.**
**Критерий:** по каждому блоку есть явное решение пользователя, зафиксированное в контексте.

### Фаза 4. Мусор и кэши
Точки мусора и команды — `references/cleanup.md`. Сначала user-проход (temp, кэши пакетных менеджеров, браузерные Cache, корзины по выбранным дискам, установщики по списку). Затем собери всё elevated в **один проход** (Windows\Temp, SoftwareDistribution, DeliveryOptimization, системные остатки, DISM `/StartComponentCleanup`) — шаблон `scripts/elevated-cleanup.ps1`, запуск только через **`scripts/run-elevated.ps1`** (он делает parse-check ДО окна UAC). Перед промптом: «сейчас появится окно UAC — подтверди» → прочитай лог скрипта (не консоль). Удаление — **группами**, одним батчем, не растаскивай на одиночные UAC-спамы.
**Критерий:** по каждой цели `Test-Path` → `removed` / `already gone` / `LOCKED`; дельта зафиксирована и записана в ledger.csv; невыполненное (LOCKED) помечено и попадает в итог.

### Фаза 5. Программы
Удаление строго по списку:
- определяй тип (MSI/Inno/NSIS/Squirrel/InstallShield/UWP/Portable/Steam/WSL/LocalDB/служба) — таблица и тайм-ауты в `references/cleanup.md`;
- останови процессы и службы до удаления;
- **перед запуском каждого антинсталлера предупреди**: «сейчас может открыться окно деинсталлятора — это нормально, это не наш скилл, а сама программа; подтверди/дождись». Не все Inno уважают `/VERYSILENT`, а некоторые требуют ручного щелчка — ожидай это и не считай ошибкой;
- после каждой — **обязательный residue-check**: `scripts/residue-check.ps1` (процессы → службы → задачи → Run-ключи → ярлыки → папки → реестр HKLM+WOW6432+HKCU) + `Test-Path` папки/ключей. **Не верить exit-коду антинсталлера** — проверять результат самому. **Папку не удалять, пока не сверен реестровый кросс-чек** (в своих каталогах вроде `D:\Soft` соседние приложения живут рядом);
- отмечено: после удаления программы могут появиться битые ярлыки (Старт-меню) — это заберёт Фаза 8, но дешёвый ре-скан `shortcuts.ps1` можно прогнать сразу;
- MSI-установки — во второй elevated-проход (в идеале сессия тратит **≤2 UAC-прохода** всего, жёсткий потолок — 3; сгоревшие из-за сбоя промпты считаем отдельно и при необходимости дозапрашиваем с явного «да»).
**Критерий:** каждая выбранная программа → удалена (подтверждено residue-check) / `LOCKED`-pending (с пометкой) / «не удалена по решению пользователя»; результат по каждой в ledger+лог.

### Фаза 6. Профиль и данные
Обход AppData Local/Roaming/LocalLow + ProgramData + корень профиля (со скрытыми). Карта и кросс-референс папка ↔ установлено — `references/deep.md`. Сироты (папки/данные без установленного владельца) собираются в блок. **Сейвы** (LocalLow по студиям, My Games, Saved Games) — категория «спорное»: **отдельный вопрос**, риск-класс 🔴.
**Критерий:** каждый остаток помечен «удалён» или «оставлено (решение)» — после реестрового кросс-чека перед удалением папки.

### Фаза 7. Автозапуски
Все источники: Run/RunOnce (HKCU+HKLM+WOW6432Node), Startup-папки (user+ProgramData), задачи (`TaskPath -notlike '\Microsoft\Windows\*'` + Actions), службы Auto, Winlogon, StartupApproved — команды в `references/deep.md`; полный отчёт со статусами строит **`scripts/autostart.ps1`**.
Покажи пользователю **весь список**, а не только битые: по каждой записи — источник, команда/цель, статус (LIVE / BROKEN / спец) и **предложение на выбор**: удалить программу целиком / отключить автозапуск (`sc.exe config <svc> start= disabled` · `Disable-ScheduledTask` · убрать Run-значение) / оставить. Пользователь может не знать, что у него в автозапуске — решение всегда за ним. Голые имена exe (резолвятся через %PATH%) и shell-/`::{}`-таргеты битыми не считаются (README: см. parser-логику в `cleanup-common.ps1`/`autostart.ps1`).
**Критерий:** по каждой записи зафиксировано решение (оставить/отключить/удалить), битые удалены (или LOCKED), отчёт в лог.

### Фаза 8. Битые ярлыки
Desktop user+Public, Start Menu user+ProgramData; `.lnk` и `.url`. Скрипт `scripts/shortcuts.ps1`. Битые = цель не существует.
**Критерий:** все ярлыки проверены, битые удалены, сосчитаны (напр. «65 битых, 212 целых»).

### Фаза 9. Рекомендации
Два блока (всё из `references/final-options.md`):
- **Системное** (риск-опции): `powercfg /h off` (hiberfil ≈ 40% RAM — объяснить: «отключит гибернацию», рекомендация только если место важнее фичи), DISM `/ResetBase` (без отката обновлений), `vssadmin resize` (тени: **замер `vssadmin list shadowstorage` уже в Фазе 2/elevated-проходе** — на прогоне C: показывал 16 ГБ при лимите UNBOUNDED — это главный нереализованный рычаг), удаление драйверов. Каждая — с «на что влияет» + условием рекомендации; выполнение только по явному «да» с осознанием последствия, желательно в тот же UAC-батч.
- **Встроенные команды** (действия пользователя, объяснить как запустить): `cleanmgr /sagerun:1`, `chkdsk /scan`, `Optimize-Volume -ReTrim`, Storage Sense.
**Никаких предложений установки сторонних инструментов** (WizTree и т.п.) — если пользователь спросит, реши ad hoc без скилла.
**Критерий:** каждая опция объяснена; одобренное исполнено или зафиксировано «отложено».

### Фаза 10. Итог
Итог строй по **`ledger.csv`** (`scripts/ledger-report.ps1`): baseline (записан в Фазе 0) → освобождено по фазам (сумма `removed_mb`) → актуальная дельта томов по `Get-Volume`. Итоговый отчёт: «свободное место: было X → стало Y, **освободилось N ГБ**» (по каждому целевому тому и суммарно) → удалено по категориям (с суммами из ledger) → **оставлено осознанно** (с причинами) → **требует перезагрузки/действия** (LOCKED-pending, PendingFileRenameOperations, `wsl --uninstall`) → советы. Запиши отчёт в кумулятивный файл и покажи. Отдельного предложения «найти неиспользуемые» в конце НЕ делаем — кандидаты уже собраны в Фазе 2 (`unused_hints.txt`) и показаны в Фазах 3/5 как блок 🔵 (с оговорками из `references/final-options.md`).
**Критерий:** отчёт сформирован из ledger.csv, записан в файл + показан; каждая фаза имеет запись в ledger.

## Pitfalls

- **`Del` — алиас `Remove-Item`**: функция с именем `Del` молча не вызывается. Аналогично — **любые имена-ключевые слова** (`Do`, `ForEach`, `Dir` и т.п.): скрипт может молча не загрузиться или упасть на парсинге (реальный кейс: `Do`-функция в elevated-скрипте). Используй глагол-существительное (`Remove-Target`, `Do-Clean`, `Write-Ledger`).
- **Перед elevated-запуском всегда `[Parser]::ParseFile`** — дешёвый способ не жечь UAC впустую; готовый шаблон — `scripts/run-elevated.ps1`.
- **`return $null` внутри `ForEach-Object` (пайплайн) — НЕ завершает функцию**: эмитит $null в вывод (массив @($null, path)), из-за чего `if (-not $x)` и параметры ломаются. Собирай результат через `foreach`-цикл / `[ref]` и проверяй `[string]::IsNullOrEmpty`.
- **Счётчики `$x +=` внутри функции — локальная копия** (скоуп): «ИТОГО» в логе может соврать в разы (реальный кейс: показано 0,86 ГБ при фактических ~2,7). Агрегируй через `$script:`/`[ref]`, либо возвращай объект; итог всегда сверяй с `Get-Volume`-дельтой.
- **Таб только в двойных кавычках**: `'...`t...'` — это литеральные backtick+t, а НЕ таб (эскейп-последовательности в одиночных кавычках не работают). Все форматы `"{0}`t{1}"` — в двойных. (Реальный кейс: разделители в отчётах scan/Dupe превратились в `t и сломали сортировку-сплит.)
- **Запуск из git-bash (Hermes)**: путь `-Root "C:\"` рвёт кавычку на завершающем `\` → используй `C:/`. В шапках скриптов примеры уже с `/`.
- **`-LiteralPath` всегда** — кириллица, пробелы, скобки. **`-Include`/`-Exclude` не работают с `-LiteralPath`** (молча пропускают фильтр) — фильтруй по `Extension` явно через `Where-Object`.
- **Ярлыки**: `.url` — это INI-содержимое (`URL=`), пустая точно-цель COM — не всегда битая (shell-объекты «Этот компьютер», `shell:`/`::{}`-таргеты) — битый = конкретный несуществующий путь к файлу. Поведение зашито в `scripts/shortcuts.ps1`.
- **Автозапуски**: голые имена exe (`powershell.exe`) резолвятся через %PATH% и НЕ битые; PathName служб может содержать двойные `\\`; пути с пробелами без аргументов — учитывать целиком. Парсер в `cleanup-common.ps1`/`autostart.ps1`.
- **После каждого удаления — `Test-Path`**: `removed / LOCKED / already gone`. `SilentlyContinue` прячет провалы — не полагайся на него.
- **LOCKED-процедура**: ретрай → `Stop-Process` держателя → остановка SearchIndexer (часто не помогает) → `scripts/pending-delete.ps1` (PendingFileRenameOperations — удаление при перезагрузке).
- **UAC-дисциплина**: не спамим. Один промпт на проход, цель ≤2 прохода/сессия (потолок 3). **Сгоревшие из-за сбоя промпты считать отдельно** от рабочих и при необходимости дозапрашивать с явного «да». Отменённый UAC → «не выполненное» в отчёт, спросить в конце один раз; повторный промпт — только по явной просьбе.
- **Тайм-ауты**: MSI 240–300 с; весь прямой elevated-проход целиком 30–50 мин; сканы 1–10 мин (single-pass `scripts/scan.ps1` — в разы быстрее старых кастомных обходов; параллельные сканы на SATA-SSD конкурируют за диск и суммарно медленнее).
- **Логи UTF-8** — иначе кириллица битая; читаем лог, а не консоль.
- **%TEMP% не хардкодить**; рабочая папка — никогда не удалять и **исключать из обхода** сканов (иначе самополлюция результатов).
- **Неизвестное на системных томах** (корень `C:\Windows`, корни дисков): перед удалением проверить дату создания, тип, подпись, происхождение — и спросить.
- **Не удалять данные установленных приложений** — реестровый кросс-чек до удаления папки.
- **settings-less тихие установщики**: если папка уже удалена, антинсталлер может вернуть «MISSING» — это не ошибка, чистим реестр.
- **`Get-Volume .DriveType` — enum**: сравнивать с исключениями (2 съёмный / 4 сетевой / 5 CD), а не с `-eq 3` (не срабатывает). Корзину считаем только по файлам `$R*`.
- **Дубли на системных путях** (WinSxS/NGEN/DriverStore/lxss) — by-design шум; выноси в `dupes_system.txt`, в `dupes.txt` оставлять только пользовательские кандидаты.
- **Леджер (CSV)**: никаких строк до заголовка (комментарий станет шапкой для Import-Csv); для сортировки/счётчиков не полагаться на `Sort-Object`-scriptblock на сотнях тысяч объектов — использовать инкрементальный top-N аккумулятор.
